In this document, you'll learn how a product is tied to the store that sells it.

## Product seller

The `product_seller` table links Medusa's `Product` to Mercur's `Seller`. The
link is created for the submitting store when a product is created with
`seller_ids`, and it is what scopes every vendor product route to that store.

```ts
const { data: products } = await query.graph({
  entity: "product",
  fields: ["id", "title", "sellers.id", "sellers.name"],
  filters: { id: "prod_123" },
})
```

A product has exactly one store. The order split reads the line item's store
from `variant.product.sellers[0]`, so a product must not be linked to a second
store, and a product without a store cannot be checked out.

<Warning>
  The link is defined as a list on both sides and
  `linkSellersToProductWorkflow` can still add or remove stores. Use it only to
  move a product to another store (remove the old store and add the new one in
  the same call), never to attach a second store.
</Warning>

## Category link

Product categories carry a similar `category_seller` link between
`ProductCategory` and `Seller` that scopes which categories a store is
associated with. Manage it with `linkSellersToProductCategoryWorkflow`.
