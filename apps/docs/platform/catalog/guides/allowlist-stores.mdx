In this guide, you'll learn how a product moves from one store to another.

A product belongs to exactly one store (see
[the product–seller link](/platform/catalog/concepts/product-seller-allowlist)).
The move is a single call: `changeProductSellerWorkflow`, exposed to the admin
panel as `POST /admin/products/:id/seller`.

## Move a product

```ts title="src/api/custom/move-product/route.ts"
import type { MedusaRequest, MedusaResponse } from "@medusajs/framework/http"
import { changeProductSellerWorkflow } from "@mercurjs/core/workflows"

export async function POST(req: MedusaRequest, res: MedusaResponse) {
  await changeProductSellerWorkflow(req.scope).run({
    input: {
      product_id: req.params.id,
      seller_id: "sel_new",
      shipping_profile_id: "sp_of_sel_new",
    },
  })

  res.sendStatus(200)
}
```

The workflow:

- requires a shipping profile of the new store,
- deletes the stock levels in the old store's locations (the new store enters
  its own stock) and moves the inventory items to the new store,
- refuses the move while stock is reserved for unshipped orders, or while a
  promotion rule or price list of the old store still names the product.

Past orders stay with the old store.

## Link a category

Categories use the same shape through `linkSellersToProductCategoryWorkflow`,
scoping which stores a category is associated with:

```ts
import { linkSellersToProductCategoryWorkflow } from "@mercurjs/core/workflows"

await linkSellersToProductCategoryWorkflow(container).run({
  input: {
    id: "pcat_123",
    add: ["sel_123"],
  },
})
```
