In this guide, you'll learn how to change which store a product belongs to by
updating the `product_seller` link from your own server code.

A product belongs to exactly one store (see
[the product–seller link](/platform/catalog/concepts/product-seller-allowlist)).
Mercur exposes `linkSellersToProductWorkflow` to add and remove store links in a
single call, so a move removes the old store and adds the new one together.

## Move a product

```ts title="src/api/custom/move-product/route.ts"
import type { MedusaRequest, MedusaResponse } from "@medusajs/framework/http"
import { linkSellersToProductWorkflow } from "@mercurjs/core/workflows"

export async function POST(req: MedusaRequest, res: MedusaResponse) {
  await linkSellersToProductWorkflow(req.scope).run({
    input: {
      id: req.params.id, // product id
      add: ["sel_new"],
      remove: ["sel_old"],
    },
  })

  res.sendStatus(200)
}
```

<Warning>
  Never leave a product with two stores or with none: the order split takes the
  first linked store as the line item's store, and a line item without a store
  is rejected at checkout. The product's shipping profile and stock locations
  belong to the old store, so move or recreate them for the new store too.
</Warning>

## Link a category

Categories use the same shape through `linkSellersToProductCategoryWorkflow`,
scoping which stores a category is associated with:

```ts
import { linkSellersToProductCategoryWorkflow } from "@mercurjs/core/workflows"

await linkSellersToProductCategoryWorkflow(container).run({
  input: {
    id: "pcat_123",
    add: ["sel_123"],
  },
})
```
